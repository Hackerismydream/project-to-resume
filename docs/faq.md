# FAQ

## Does it rewrite an entire resume?

Its primary product is repository-to-project-experience translation. It can optimize existing project sections, but it is not a PDF layout or application-submission service.

## Does it need a repository?

A repository is preferred. With only a resume or project description, it can improve existing statements without inventing implementation. With only a JD, it must request project material instead of generating experience.

## Will it run project code?

No by default. Repository analysis is read-only. Existing commands may run only with explicit user authorization and a safe environment, and results remain bound to the exact revision and environment.

## Why can a project have only one or two bullets?

Bullet count follows independent role signals. Padding a project with duplicate mechanisms or peripheral features reduces evidence density and creates interview risk.

## Do tests prove reliability?

Test source proves that scenarios were written. A recorded run proves those scenarios passed under stated conditions. Neither alone proves production reliability or business impact.

## Can a public repository be written as my personal contribution?

Not automatically. State whether it is your project, team work, a fork, or an upstream contribution, and identify what you personally implemented or validated.

## Does the project claim to improve interview or offer rates?

No. Such claims require real user studies with documented attribution and confounders. Current automation validates package contracts, not hiring outcomes.
