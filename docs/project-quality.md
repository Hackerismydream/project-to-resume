# Project Quality Bar

A change is ready to merge when it improves a concrete repository-to-resume behavior, survives counterevidence, keeps Claims within sources, preserves privacy, has an appropriate deterministic or fixed-case regression, and leaves the first-use path simpler or unchanged.

A larger diff is not inherently more complete. Prefer deleting duplicated instructions, keeping one canonical document per concern, and linking from README or the documentation index. New files should have a clear owner, audience, and maintenance reason.
