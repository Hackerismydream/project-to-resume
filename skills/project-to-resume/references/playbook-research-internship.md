## 1. 科研项目

科研经历使用：

```text
问题定义 → 数据集/任务 → Baseline → 方法变化 → 实验设计 → 结果 → 个人贡献与边界
```

### 问题定义

说明对象、输入、输出、约束和现有方法失败在哪里。不要用论文标题代替问题。

### 数据与任务

准备：数据来源、规模、划分、标签、预处理、类别分布、泄漏检查和许可边界。自建数据集要说明标注或构造方法。

### Baseline

只比较实际运行或论文实验明确包含的 baseline。说明模型、版本、配置和公平性；不要把不同数据、不同 prompt 或不同预算的结果直接比较。

### 方法

写清候选人改变了哪个行为，而不是列模型名：

- 改变特征表示；
- 改变训练目标或奖励；
- 改变检索/推理路径；
- 改变数据构造或采样；
- 改变部署、推理或评测流程。

### 实验与结论

优先写：主结果、关键消融、失败实验和结论边界。局部指标提升但主任务退化时，不能写正面优化。

### 个人贡献

论文是团队成果。区分：问题提出、数据构建、模型实现、实验、分析、论文写作和开源。作者排序不能自动证明全部贡献。

## 2. 实习项目

实习经历先写真实业务和本人链路，不要写成学生项目说明书。

内部梳理：

```text
团队目标 → 服务对象 → 业务流程 → 本人职责 → 协作边界 → 交付物 → 验收/上线 → 故障与复盘
```

优先故事：

- 负责的核心接口、工作流或模块；
- 与产品、前端、测试、数据或下游团队的口径对齐；
- 异常、性能、数据或稳定性问题；
- 真实上线、验收、用户反馈或维护责任；
- 一次故障定位或 badcase 闭环；
- 沉淀的模板、工具、文档、评测或自动化流程。

实习 title 不利于目标岗位时，可以调整叙事入口，但不能伪造岗位。例如“模型评测实习”可以写成“大模型应用工程化交付”主线，但不能冒充负责后端系统开发。

## 3. 团队结果与个人职责

把一段经历拆成三层：

| 层 | 写法 |
| --- | --- |
| 团队/系统背景 | 项目描述中说明整体目标 |
| 本人职责 | bullet 使用明确个人动词和负责链路 |
| 团队结果 | 用“项目/团队达到”，或说明本人贡献与结果的关系 |

不要自动把以下内容全部归给个人：

- 整个平台的用户数、营收或整体性能；
- 团队上线的所有模块；
- 论文或开源项目的全部设计；
- 多人共同完成的模型、数据和基础设施。

可以写：

> 负责意图识别三阶段路由中的规则与向量匹配链路，参与 7 类高频意图边界梳理；项目在固定验证集上……

不要写：

> 主导整个智能助手平台并将所有意图准确率提升……

除非用户明确确认。

## 4. 开源与二次开发

先区分：

```text
上游已有能力 | 本人新增能力 | 本人修改能力 | 本人集成/部署 | 本人验证
```

标题根据已确认归属选择：

- 未确认责任范围：`项目名：XX 能力扩展｜开源贡献`；
- 用户明确负责核心二次开发：`基于 XX 的领域 Agent 二次开发｜核心开发`；
- 用户明确从零独立完成插件或适配器：`XX 插件 / 适配器｜独立实现`。

“核心开发”和“独立实现”不是默认模板；只有责任事实明确时使用。

推荐 bullet：

- 说明上游问题或缺口；
- 说明本人修改的模块和外部行为；
- 说明兼容性、回归、PR、issue 或发布结果；
- 说明没有覆盖的边界。

不要把运行开源项目、修改配置、换 Prompt 或接一个 API 写成“从零设计并实现”。

## 5. 隐私和披露边界

实习和私有项目不要输出：

- 客户名称、内部 URL、密钥、表名、账号和路径；
- 未公开业务规模、收入、事故或模型指标；
- 可识别个人的用户数据；
- 公司禁止披露的架构、策略和日志。

使用抽象但可讲的表达：

- “内部研发平台”“某业务系统”“5 万级脱敏客户库”；
- “下游服务”“统一状态口径”“请求级 trace”；
- “固定验证集”“脱敏 badcase”。

不能披露不等于可以编造。缺少可公开细节时缩小范围。

## 6. 高风险写法

- 把研究原型写成生产系统；
- 把论文计划、在投稿件或复现结果写成已发表个人成果；
- 把公司 title 改成职责完全不同的岗位；
- 把测试、标注或评测工作全部包装成平台核心研发；
- 把团队整体结果归因于个人；
- 把 fork、配置和集成写成从零自研；
- 把模拟数据、课程数据写成真实业务数据；
- 为了保护隐私删除到只剩空洞技术名词。

## 7. 面试防御

### 科研项目

准备：问题定义、数据、baseline、公平比较、方法、关键消融、失败实验、结果边界和个人贡献。

### 实习项目

准备：组织目标、本人链路、上下游、需求来源、技术取舍、上线/验收、一次故障、协作冲突和复盘。

### 开源贡献

准备：上游原行为、修改位置、为什么这样改、兼容性、测试、PR/issue、维护状态和没有解决的问题。

如果候选人无法明确说出“我做了什么、团队做了什么、系统已有能力是什么”，先降级个人动词。
