## 行为链路

### 链路 A：模型只返回推理内容或空正文

```text
Agent Loop 收到无可见正文的模型响应
→ 检查结构化推理内容和行内思考标记
→ 选择推理回填或原样重试
→ 按本轮独立预算继续请求
→ 得到可见正文，或预算耗尽后交付有界兜底结果
```

### 链路 B：工具调用后模型没有给出正文

```text
前一轮已经执行工具
→ 下一次模型响应没有可见正文且不含推理内容
→ 注入短提示，要求消费工具结果或给出最终答案
→ 继续 Agent Loop
→ 临时恢复提示在持久化前移除
```

## 可直接粘贴的简历版本

**Pico 多入口 Agent Runtime｜Agent Runtime 开发**

**技术栈：** Python、大语言模型、Tool Calling、状态管理、Pytest

**项目描述：** 面向多入口共享运行时的 Agent Harness，负责模型空响应恢复模块及相关测试，重点处理工具调用后的任务收敛、恢复预算和会话状态污染问题。

1. 将无可见正文的模型响应区分为仅返回推理内容、工具调用后无正文和普通空响应，分别采用推理回填、短提示和原样重试，并以每轮独立预算限制恢复次数，避免任务直接交付空答案或陷入无限循环。
2. 将恢复判断抽成无 I/O 纯函数，由 Agent Loop 统一执行消息注入、计数和持久化清理；围绕恢复优先级、预算耗尽、兜底结果及临时恢复消息不落盘编写回归测试场景。

## 常见面试追问

1. 为什么“仅返回推理内容”应优先于工具调用后的短提示，预算耗尽后为什么还保留普通重试？
2. 临时恢复消息为什么不能持久化，落盘后会怎样影响下一轮上下文？
3. 怎样设计 forward eval，判断恢复提高了任务完成率，而不是只增加模型调用次数？
