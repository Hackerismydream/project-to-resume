# Support

For reproducible installation, validation, or output-contract problems, open a structured GitHub Issue using the appropriate template.

Before opening an issue:

1. Confirm the exact `project-to-resume` commit.
2. Run `make check` when the problem concerns this repository.
3. Reduce repository examples to a public fixed revision or synthetic fixture.
4. Remove private resumes, credentials, internal code, customer data, and personal information.
5. State what behavior you expected and what actually happened.

Use:

- **Bug report** for reproducible installation, validation, routing, or output-contract failures;
- **Feature request** for a concrete missing behavior with an evaluation plan;
- **Documentation correction** for stale instructions, broken links, or unsupported public claims;
- **Showcase submission** only for authorized, anonymized Before / After examples.

Security vulnerabilities and privacy incidents must not be filed publicly. Follow [SECURITY.md](SECURITY.md).

The project does not provide private resume review, job-placement guarantees, or response-time guarantees through the public issue tracker.
