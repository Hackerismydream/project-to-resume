# 示例：实习 + 个人项目 + JD

## 用户输入

目标 JD 反复提到：Python 服务、RAG、LLM 工作流、异步任务、质量评测和异常兜底。

用户现有材料比较零散：

```text
实习：内部研发知识助手。我负责文档入库、检索和回答引用。
文档会更新和删除，不同团队只能看自己的资料。
技术是 Python/FastAPI/PostgreSQL/pgvector/BM25/reranker。
做过 80 条固定问题，同一数据和 Top-5 下，纯向量召回命中 61 条，混合召回命中 73 条。

个人项目：本地代码 Agent，Python/Pydantic/SQLite。
有模型循环、工具 schema、路径权限、checkpoint、取消和终止原因。
做过中断恢复、非法参数、工具超时等固定测试，但没整理性能数字。
```

## 可直接粘贴的简历版本

**内部研发知识检索与问答系统｜AI 应用开发实习**

**技术栈：** Python、FastAPI、PostgreSQL、pgvector、BM25、Rerank

**项目描述：** 面向内部研发人员查询分散技术资料的场景，负责文档入库、检索、重排与引用回答链路，并处理知识更新、访问权限和无有效证据时的回答边界。

1. 设计文档解析与增量入库流程，保留来源、版本和团队权限元数据，使更新与删除能够传播到检索索引。
2. 融合 BM25 与向量召回候选并统一重排；在同一数据、Top-5 和 80 条固定问题下，证据命中数由纯向量方案的 61 条提升至 73 条。
3. 在召回和上下文组装前执行团队权限过滤，避免无权限片段进入模型输入与引用结果。
4. 为低相关和无结果查询设计拒答与人工检索入口，保留回答引用，避免缺少证据时直接生成确定性结论。

**面向代码仓库任务的本地 Agent Runtime｜Agent 工程**

**技术栈：** Python、Pydantic、SQLite、大语言模型、Tool Calling

**项目描述：** 面向本地代码仓库的多步修改任务，实现模型决策、受控工具执行、状态持久化与终止管理，重点处理非法调用、任务中断和工具副作用边界。

1. 实现 Agent 任务循环与显式终止状态，串联模型决策、工具请求、执行结果和后续动作，并区分完成、取消、工具失败与模型提供方失败。
2. 通过结构化 Schema 校验工具参数，并对文件路径和执行权限进行约束，使非法请求在进入有副作用的工具前被拒绝。
3. 使用 SQLite 持久化会话 Checkpoint 与执行状态，支持进程中断后加载已保存状态，并将用户取消和工具失败记录为不同终止原因。
4. 围绕中断恢复、非法参数、工具超时和用户取消编写固定回归用例，检查任务的预期终态和可追踪记录。

## 示例要点

- JD 只改变两个项目的顺序和观察角度，没有补造 Kafka、Celery 等关键词。
- 实习项目的检索数字保留了 baseline、Top-K、样本数和绝对命中数，没有泛化成“准确率提升 20%”。
- 第二项目没有可信性能结果，因此写故障场景和验证行为，不补造成功率或延迟。
